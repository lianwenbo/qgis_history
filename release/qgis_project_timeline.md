## 第一阶段 · 校准入门与经纬线基础设施

> **时间范围**：2026-06-19 项目初始化 → **2026-07-24** 经纬线拟合方案重构 commit（历时 36 天）
>
> **覆盖 CONV**：`6a19bbc2` → `6a602eb8` → `6a65fa5d`（最早 3 个 CONV，约 40 task）
>
> **关键 git commit**：`3b98f67`（6-19 初始化）→ `ea9f590`（7-04 四类分割）→ `077ada7`（7-24 拟合重构）

### 核心亮点

1. **问题定义**：目标是把 JPG 扫描件校准进 QGIS（生成 GeoTIFF），作为所有后续要素提取的前提。
2. **GCP 概念建立**：从零理解 GCP 是什么，形成了"经纬线交点=GCP"的基本判断。
3. **大图 vs 子图校准规模**：讨论了单张子图 5 点 vs 一张大图 20-30 点的取舍，最终结论是大图优先，子图会让 GCP 不足。
4. **4 个交叉点不够**：意识到经纬网格 4 角（上下左右各 1 个）残差过高，需要至少 5 个以上 GCP，且交叉点通常不在四角，需要额外补点。
5. **LabelMe 交点自动生成流水线雏形**：`LabelMe 经纬线直线 → 自动求像素交点 → 拼成 QGIS .points 格式的 GCP 文件`，这是所有后续自动化的基础。
6. **纬线序号 bug（首次真实验证）**：陇右道东部的纬线识别结果错了（应从 32° 起算），暴露了"标签的经纬度序号绑定错误"这类深 bug，第一次证明了人工校验的必要性。
7. **配准后 TIFF 颜色/重采样质量担忧**：第一次意识到 JPG → GeoTIFF 的重采样损失可能影响 CV，这个担忧直到 8 月 7 日通过 `gcp/*.tif` 质量分析才被量化解决。
8. **插图（Inset Map）禁选点规则**：发现图中小插图比例尺独立，明确了"插图区域 GCP 直接剔除"的硬规则。

### 阶段结束时的基本链路

```
经纬线人工标 LabelMe（直线） → 自动求交点 → QGIS .points GCP 文件 → 配准 → TIFF
```

这个链路之后从未被推翻，只是每个环节不断被优化和自动化。

## 第二阶段 · 子图切割探索 & SAM 岔路（首次重大分叉）

> **时间范围**：2026-07-06（滑窗推理 commit）→ **2026-07-27**（分隔线检测重构 commit）（历时 21 天）
>
> **覆盖 CONV**：`6a6334cd`（子图切割）→ `6a670f49`（SAM 岔路）→ `6a68479c`（色带+蓝虚线特征确立）
>
> **关键 git commit**：`fff1a08`（7-06 滑窗推理）→ `e347a3a`（7-27 分隔线重构）

### 核心亮点

1. **深色粗线分图算法**：谭图单张扫描件常含 2-3 张子图，需自动切割；引入骨架化单像素切割 + class=3 色聚类思路，但切割精度始终在「能用但不稳」的水平。
2. **SAM 岔路（你第一次硬决策）**：
   - 提出用 Segment Anything 直接划行政区划多边形。
   - 经过多轮讨论你**断然否决**：谭图是「色带+暗线+注记」高度混合的场景，SAM 的无提示分割完全不适用；且多边形的公共边会出现两份且彼此不一致，后续交点对齐无解。
   - **长期价值**：这个决策避免了至少 2 个月的无效投入，直接把问题定义从「面分割」拉回到「两级线 + 交点」。
3. **色带 + 蓝虚线特征的首次系统化描述（最关键的特征工程发现）**：
   > 紫红色半透明色带（区划背景色）+ 蓝色虚线/实线（真正的边界暗线）——两者不重合，不能取色带中心线作边界，必须在**色带带宽范围内或沿边缘找蓝线/暗线**。
4. **ROI 约束原则落地**：「先做色带 ROI，再在 ROI 内找边界线」，这个 ROI-first 原则一直延续到现在的所有算法（传统 Otsu、骨架吸附、逆向标注后的修正范围控制全部继承）。
5. **共享边界问题被你提前识别**：在 LabelMe 中如何存公共边（两个区划的交界是同一条线）——你很早就意识到这是面标注绕不过的坑，反而给中心线标注提供了论据。

### 阶段终局决策

先做到 `把边界的查询限制在带状边界上即可`，不追求一步到位。

## 第三阶段 · 标注形式的终极定案（18 轮反复，最曲折阶段）

> **时间范围**：2026-07-16（AutoDL 脚本合入 PR #1）→ **2026-07-22**（高纬度经线自适应合并）（历时 7 天，短但决策密度最高）
>
> **覆盖 CONV**：`6a699860`（18 sessions）
>
> **关键 git commit**：`184176e`（7-16 PR #1 merge）→ `cba2a7c`、`abafa43`（7-22 自适应合并）

### 核心亮点

1. **多边形 vs 中心线 来回拉锯 5 轮**：
   - R1：提多边形 → 公共边重复 + 不一致 → 你否决。
   - R2：提「先把容易识别的几张图（云南/淮南/岭北）先标出来训模型，再回推」 → ✅ 这就是冷启动小样本闭环的最早雏形，一直沿用至今。
   - R3：发现「单一面分割只能分不可再分区划，无法表达刺史部-郡 / 省道-府州的两级结构」 → 直接催生了 `boundary_1（粗线，一级）/ boundary_2（细线，二级）` 两级分类标注体系。
   - R4：提「带内不一致色的线优先于色带中心 + 断裂处向前弥合」 → ✅ 这个特征观察被直接写进后续骨架吸附逻辑的初始化版本。
   - R5：又试一次多边形 → 你再次坚决否决「共享边问题还是没解决」。
2. **标注形式拍板（沿用至今未动摇）**：
   - 形状：`linestrip` 中心线，**不用 polygon**。
   - 分类：`boundary_1`（粗/外围省-道级）+ `boundary_2`（细/内部府-州级）两级。
   - 黄金小样本集：只维护云南、岭北行省北部、淮南道 3 张图作为起点。
3. **「中心线 vs 多边形 vs QGIS 矢量化」三者关系澄清**：中心线→QGIS 里再构面是可行路径，反推（多边形→中心线）困难且易错。
4. **首次直面 8 张图里 4 张识别失败的系统性问题**：
   - 司隶校尉部：河流/地名被误进 mask（本质是颜色泛化性差）。
   - 陇右道安西都护府：内部划分不清晰（边疆制图画法写意）。
   - 广东：色带中的中间线条丢失（印刷/扫描质量问题，后续在 JPG 质量分析中被量化证实）。
   - 黑龙江：部分线条没检出（同质量问题）。
5. **LabelMe 端点合并策略**：你开始思考「多条 linestrip 首尾连在一起应该合并」的规则，为 Phase 4 的 `merge_lines` 复杂性埋下伏笔。

### 阶段产物

- `boundaries/labelme/` 下 3 张黄金集正式成为后续所有训练/验证的锚点。
- 两级中心线标注体系成为全项目宪法级规则。

> **时间范围**：2026-07-18（验证流水线 commit）→ **2026-07-31**（bound retrive v1 提交前，吸附逻辑被最终移除）（历时 13 天）

>
> **关键 git commit**：`fea6523`/`81fdedc`（7-18 验证流水线）→ `889a69d`/`c8c9c29`（7-25 训练参数微调）→ `4a45cc3`（7-31 最终边界 v1，吸附已被移除）

### 核心亮点（几乎每个点都是你拍板的）

1. **AutoDL 训练脚本落地**：第一个 `unet_boundary.pth` 和 `unet_map_lines_autodl_colab_20260720_*.pth`（经纬线模型）产出，你第一次把「校准经纬线模型」和「边界提取模型」分开训。
2. **新问题批量爆发**：
   - 色带旁的蓝色-.-花纹干扰（非边界暗线误被吸收）。
   - 二级细线（boundary_2）提取能力严重不足 → 引出「线宽训练集扩大」这个后续训练侧的方案。
3. **骨架线锯齿 + 暗线不贴合**的核心痛点触发了 5 轮吸附迭代：
   | 轮次 | 方案 | 你最终否决的原因 |
   |---|---|---|
   | R0 | 逐点 `snap_points_to_darkline` | 锯齿+连贯性差 |
   | R1 | 全局 Dijkstra 智能剪刀 | 耗时爆炸你手动 kill；起止点不在暗线时表现灾难 |
   | R2 | 锚段/浮动段 + 局部 Dijkstra + 动态 ROI buffer | 浮动段 ROI 过大仍慢；暗线断裂区会错误吸到水系暗线 |
   | R3 | ROI O(1) 距离图 + max_snap=5 + safe_zone | 解决性能但跳变仍偶发 |
   | R4 **终局** | **你强烈要求彻底移除所有吸附逻辑，零容忍不可恢复跳变** | 吸附引入的错误比解决的还多，且不可审计 |
4. **吸附被移除后，骨架参数调优收敛**：
   - 取消二次 smooth+simplify（之前让线条直线化太严重）。
   - D-P epsilon 4.0 → 2.0，保留更多中间节点描述曲线。
   - 最终后处理链**定死**：`纯骨架 → 15px 弥合 → 合并 → 7点滑动平均 → D-P 2.0`。
5. **你最敏锐的天花板判断**：
   > 骨架中心化天然有 10px 偏差（色带宽不对称时，暗线常在色带侧边而非中心），后处理永远补不回来。
   
   这个判断直接引出了训练侧「A 扩线宽训练 / B Heatmap 中心线回归」的两条路，为 Phase 8 的逆向标注提供了认知铺垫。
6. **死代码清理（边界但重要）**：`merge_lines` O(N³)、Dijkstra costmap 过大这两个性能炸弹被识别出来，你要求所有迭代循环加硬上限，避免死循环。

### 阶段终局硬教训

「**局部后处理的吸附，在暗线断裂、水系/注记颜色干扰时，一定会引入不可审计的错误吸附，宁可不吸，也不接受跳变**。」
这条教训直接解释了为什么后来「逆向标注」（从地理真值出发）比「从像素中硬挖边界」更稳。

### 核心亮点

1. **河流识别学术界 SOTA 调研**：MapSAM 冷启动预标 → Active Learning 迭代 → 多任务+地理先验约束（连通性、不跨边界），这三阶段架构后来直接被整合进你的 Phase 6 全景蓝图中。
2. **CHGIS V4 TS 版本必须按年份过滤**：首次明确「CHGIS Time Series 版本的 SHP 每一条几何都要做 SQL：`BEG_YR ≤ 1820 ≤ END_YR`」，避免了后来逆向标注时「把 1911 年的几何套在 1820 年」的系统性错误。
3. **💥 误删危机（最严重的流程事故）**：清理 boundaries 目录时，除 labelme 外的子目录+脚本被删，引发信任和流程的剧烈震荡。
   - 直接后果：你要求「接下来只讨论方案、不写代码、不执行删除」，所有后续动作进入「原子化 + 人工确认」的严格模式。
   - 长期价值：把「破坏性操作」的风险控制提到了最高优先级，后续 `recover_quality.py` 等都严格遵守「只读输入 + 仅写新文件/新目录」。
4. **清理后保留骨架 7 脚本**：语法检查、import 依赖验证全通过。清理反而让项目结构第一次变得清晰。
5. **回归传统算法：generate_labelme_2class.py 作为冷启动**：
   - 核心思想：`Lab a* 通道取色 → 距离变换 → Otsu 阈值粗细两级分类`，绕过 DL 训练直接能出结果。
6. **云南删除二级后一级断裂的根因定位（经典）**：
   ```
   全局像素级 Otsu 按「单个像素的粗细概率」判 1/2 级 → 同一条 1 级线因印刷/扫描波动，细段被误归到 2 级
   → 删二级时 → 整条线被挖断
   ```
   - 你给出的修复方向：**线段级 Otsu（整条线段取中位数/均值定级别）+ flags 标记疑似错段供人工审校**。
7. **你第一次提出「标注是最大瓶颈」的判断**：`最难的是语料标注——量大+不准`，直接引出 AI 预标+人工纠偏+主动学习三件套。
8. **图例 OCR 冷启动工具链**：`PaddleOCR 定位图例文字 → CV 提取图例符号模板 → 全图匹配/分割`，你明确这个是「第 0 轮工具，用来降低起步难度」。

## 第七阶段 · 校准（配准）质量纠偏——解决 20km 漂移

> **时间范围**：**2026-08-05**（清理事故后，残差问题被反复讨论）（历时 1-2 天）
>
> **覆盖 CONV**：`6a7525cf` 后半部 sessions
>
> **关键踩坑**：现代同名县城点作为 GCP 导致 20km 级语义漂移，逼出了 S/A/B/C 四级 GCP 优先级

### 核心亮点（校准维度，全部是你硬踩坑踩出来的结论）

1. **现代同名县城点 = 20km 级语义漂移炸弹**：你用真实踩坑证明，误差来源不是「清朝治所 200 年间迁徙」，而是 **在边疆/边界地图上，谭图扫描件中标注的「某县城」位置（墨点）与 2026 年同名现代县城的 GPS 坐标之间存在 10-40km 级空间错位**（墨点落在现代同名县的邻县甚至邻市边界）。一旦拿现代 GPS 同名点做 GCP，就会把整条配准链路拉偏 20km 级，是配准误差最大的单一来源。这个教训直接催生了 S/A/B/C 四级 GCP 优先级——**现代同名县点被彻底踢出 GCP 候选池**。
2. **GCP 优先级表（最终版，沿用至今）**：
   | 级别 | 来源 | 是否参与拟合 | 备注 |
   |---|---|---|---|
   | S | 经纬网格交叉点 | ✅ 最高优先级 | 唯一与「地理真值」1:1 绑定、语义零漂移的锚点 |
   | A | 大的河流拐弯 × 经纬线交点 | ✅ | 河弯本身在谭图中是绘制级坐标，不依赖现代行政边界 |
   | B | 湖泊锚点（最北最南最东最西） | ✅ | 大型湖泊边界变动 <10km，属于安全锚点 |
   | C | CHGIS 治所点 | 仅在残差 <10px 时保留，否则直接删 | **现代同名 GPS 点直接禁用** |
3. **漠北/边疆 4 大特有坑的系统性识别**：
   - 贝加尔湖东西向 **22% 排版压缩**（绘图者为省版面手动压扁，是画图意图而非误差）。
   - 治所位置存在**学术分歧**（谭图墨点和 CHGIS 考证坐标各用一套研究结论，差 10-40km；这不是治所"迁移"，而是学术上不同的定位判断）。
   - 插图 Inset 污染（伊犁/外蒙插图比例尺独立）。
   - 「计里画方」在漠北**不成立**——北端手动画疏、南端画密，非线性拉伸，仿射/二阶多项式都装不下 → 必须上 TPS。
4. **残差三档诊断法**：均匀偏大（模型欠拟合→升级）/ 零星 2-5 个离群点（GCP 错→删）/ 区域性偏大（排版压缩→局部加密+TPS）。
5. **漠北专用验收阈值**：平均 <6 / 单最大 <12 / 贝加尔湖区 <20，**正式把「排版压缩是原图属性」写入规则**，不再无意义追低残差。

1. **JPG 质量第一次量化定性**：
